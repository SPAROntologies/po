description
The **_Pattern Ontology (PO)_** is an OWL 2 DL ontology that formally defines patterns for segmenting a document into atomic components, in order to be manipulated independently and re-flowed in different contexts. ![The main architecture of PO.](po.png) Structural patterns allow representing document elements (such as sections, paragraphs, lists, metadata, and tables) through abstract, reusable primitives independent of specific markup syntaxes. ## Examples of use In the following subsections, we introduce some examples to showcase how to use PO. The prefixes that are used in all the examples provided below are defined as follows: @prefix : <http://sparontologies.net/example/> . @prefix po: <http://www.essepuntato.it/2008/12/pattern#> . @prefix xsd: <http://www.w3.org/2001/XMLSchema#> . ### Structural decomposition of a document section With PO, it is possible to represent document elements and how they manifest as patterns occurring within the document's stucture itself. For example, the following example shows how to use PO to model a section defined as a headed container and containing a heading block as its header and a body paragraph block containing inline text and atom elements. :section-1 a po:HeadedContainer ; po:hasName "section" ; po:containsAsHeader :heading-1 ; po:contains :paragraph-1 . :heading-1 a po:Block ; po:hasName "h1" ; po:contains :text-heading . :paragraph-1 a po:Block ; po:hasName "p" ; po:contains :text-span . :text-span a po:Inline ; po:hasName "span" ; po:contains :atom-text . :text-heading a po:Atom ; po:hasName "text" . :atom-text a po:Atom ; po:hasName "text" . ## Competency Questions PO can be used for answering several questions related to the atomic components that form a document accoridng to certain patterns. In the following subsections, some of them are introduced together with their respective SPARQL queries. The prefixes that are used in all the SPARQL queries provided below are defined as follows: PREFIX po: <http://www.essepuntato.it/2008/12/pattern#> ### CQ1 Which header elements are contained within a headed container? SELECT ?header WHERE { ?section a po:headedContainer ; po:containsAsHeader ?header . } ### CQ2 Which block elements are directly contained within a container? SELECT ?block WHERE { ?section po:contains ?block . ?block a po:Block . }
